# Provider API Audit

> Point-in-time verification of every provider adapter against current SDK/API docs, with a bug list and usage/cost metadata inventory.

**Audited**: 2026-07-04, using Context7 MCP (`resolve-library-id` + `query-docs`) against each SDK/API's current documentation, cross-referenced with the adapter code in `server/worker/providers/**` and tests in `tests/unit/providers/**`. Web search was used as a fallback where Context7 had no indexed docs for a provider (noted per provider below).

**Fix pass: 2026-07-05.** All findings marked **FIXED** below were re-verified against current docs (fresh, targeted Context7/web-search queries, cited per item) and then corrected in code, with matching test updates. `npm run test:unit -- tests/unit/providers`, `npx nuxi typecheck`, and `docs-site npm run check` all pass after these changes.

This is a snapshot, not living truth. Docs and model rosters drift; re-verify before relying on a specific claim here for a high-stakes change. See [Providers](/backend/providers) for the stable adapter-contract reference this audit does not replace.

**Legend**: **Verified** = confirmed against current docs. **Uncertain** = plausible, not independently confirmed. **ISSUE** = adapter code likely diverges from current provider behavior. **FIXED** = corrected in the 2026-07-05 pass. **OPEN** = still unresolved, left for a future pass.

## Concrete issues found (read this first)

1. **FIXED - OpenAI Images (`image/openai_image.ts`) was broken for the catalog default.** Re-confirmed via Context7 (`/websites/developers_openai_api`): GPT image models (`gpt-image-1`, `gpt-image-1.5`, `gpt-image-2`) always return `b64_json`; `response_format` is only meaningful for `dall-e-2`/`dall-e-3`. Fixed: dropped `response_format`, now reads `res.data[0].b64_json` and returns `{ rawBuffer, mimeType: 'image/png' }`. Test: `tests/unit/providers/openai_image.image.test.ts` (new - none existed before).
2. **FIXED - MiniMax (`video/minimax.ts`) had three param bugs.** Re-confirmed via Context7 (`/websites/platform_minimax_io_api-reference`): valid `duration` values are `6` or `10` only (no `5`); valid `resolution` values are `512P`/`768P`/`1080P` (both catalog models support `768P` at either duration); there is no `aspect_ratio` field in `VideoGenerationReq` at all. Fixed: `duration` now clamps `params.duration` to the nearest of `6`/`10` (`>= 8` rounds up to `10`), `resolution` is hardcoded to the valid `768P`, and `aspect_ratio` was removed entirely.
3. **FIXED - fal.ai video (`catalog.ts` + `video/fal_video.ts`) had an invalid model slug.** Re-confirmed via web search (fal.ai model pages): `fal-ai/pika-ai/pikav2.2` matched no real endpoint; real slugs are `fal-ai/pika/v2.2/text-to-video` and `fal-ai/pika/v2.2/image-to-video`. Also confirmed fal has no single uniform suffix convention - MiniMax's fal endpoint is `fal-ai/minimax/video-01` (no suffix) for text-to-video and `fal-ai/minimax/video-01/image-to-video` for image-to-video. Fixed: the catalog now stores base ids (`fal-ai/pika/v2.2`, `fal-ai/minimax/video-01`) and the adapter maps each to its real endpoint pair via a small lookup table, branching on `params.imageUrl` presence. Test: `tests/unit/providers/fal_video.video.test.ts` (new - none existed before).
4. **FIXED - Kling (`catalog.ts` + `video/kling.ts`) had two issues.** Re-confirmed via Context7 (`/websites/kling_ai_document-api`): valid `model_name` values do not include `kling-v1-pro`/`kling-v1-5-pro` ("pro" is a separate `mode` request param, values `std`/`pro`/`4k`, not part of the model name). Also confirmed the current global (non-China) host is `https://api-singapore.klingai.com`, not `https://api.klingai.com`. Fixed: catalog now offers `kling-v2-master` (default), `kling-v2-6`, `kling-v1-6`; `KLING_BASE` updated to the Singapore host. `mode` is left unset (provider default applies) - not added as a UI control in this pass.
5. **FIXED - Replicate video (`catalog.ts`) had two wrong model slugs.** Re-confirmed via web search: `wavespeedai/wan-2.1-i2v-480p` is the real, live model (`wan-ai/wan2.1-i2v-480p` 404s); `luma/ray-flash-2-540p` and `luma/ray-flash-2-720p` are the real resolution-suffixed slugs (`luma/ray2-flash` doesn't exist). Fixed: catalog updated to `wavespeedai/wan-2.1-i2v-480p` and `luma/ray-flash-2-540p`. No adapter code change needed (it generically splits `owner/model` from `params.model`).
6. **FIXED - Stability AI (`image/stability.ts`) SD3.5 selection was a no-op.** Context7 (`/websites/platform_stability_ai`) release notes confirm the `/sd3` endpoint's `model` parameter selects the variant (e.g. `sd3-medium` shown explicitly); the exact `sd3.5-large` string wasn't returned verbatim by Context7 but is Stability's documented model name for SD 3.5 Large. Fixed: the adapter now appends `model: 'sd3.5-large'` to the form when `params.model === 'stable-diffusion-3-5-large'`.
7. **FIXED (by removal) - Ideogram (`image/ideogram.ts`) V2 selection was a no-op.** Context7 (`/websites/developer_ideogram_ai`) confirms V2 lives behind a wholly different legacy endpoint (`POST https://api.ideogram.ai/generate`, JSON body shaped `{ image_request: { prompt, aspect_ratio: "ASPECT_10_16", model: "V_2", ... } }`) with no relationship to the v3 endpoint (`/v1/ideogram-v3/generate`, multipart form, no `model` field - version is in the URL). Building a second request path for one legacy model was judged out of scope for this pass. Fixed: removed `V_2` from the catalog rather than leave a selectable option the adapter can't call. Also fixed the v3 `aspect_ratio` format from `'9X16'` to the documented lowercase `'9x16'` (confirmed via the Remix v3 endpoint's example).
8. **FIXED - Together AI (`image/together_image.ts`) dropped `negativePrompt`.** Together's `images.generate` SDK type already declares `negative_prompt?: string` (confirmed in `node_modules/together-ai/resources/images.d.ts`). Fixed: the adapter now forwards `negative_prompt: params.negativePrompt` when set.
9. **RE-VERIFIED, NO CHANGE - Hugging Face image/audio/video adapters' host.** Re-checked via Context7 (`/huggingface/hub-docs`) this pass: while chat completions have clearly moved to `https://router.huggingface.co/v1/chat/completions` (already used correctly by the script adapter), HF's own current task-specific docs for text-to-video, translation, summarization, and question-answering *still* show curl examples against the legacy `https://api-inference.huggingface.co/models/{model}` host and a plain `{"inputs": ...}` body - the same shape these three adapters already use. This contradicts the original audit's assumption that the legacy host is fully superseded for non-chat tasks. No host or body-field change made; re-open this if a future pass finds stronger evidence the legacy host has actually been retired for these tasks.
   - **FIXED (by removal) - `huggingface_video`'s `ali-vilab/i2vgen-xl`** removed from the catalog: a 2023-era research model with no evidence of current Inference Providers coverage, and no confirmed working replacement found this pass. The default `Wan-AI/Wan2.1-T2V-14B` remains as the only option.
10. **FIXED - Gemini TTS (`audio/gemini_tts.ts`) model IDs were missing the `-preview` suffix.** Confirmed via Context7 (`/websites/ai_google_dev_gemini-api`): current model ids are `gemini-2.5-flash-preview-tts`, `gemini-2.5-pro-preview-tts`, `gemini-3.1-flash-tts-preview` (note the inconsistent suffix position between the 2.5 and 3.1 generations - that's what Google's own docs show). No `gemini-2.5-flash-lite-tts` model was found in current docs - only flash, pro, and 3.1 flash TTS variants are documented. Fixed: catalog updated to the three confirmed ids, dropping the unconfirmed lite variant in favor of the confirmed `gemini-2.5-pro-preview-tts`.
    - **OPEN**: current Google docs exclusively demonstrate the new `interactions.create` / `POST /v1beta/interactions` API for TTS now (a different request/response shape entirely from the `generateContent` + `responseModalities: ['AUDIO']` pattern this adapter still uses). Whether the legacy `generateContent` pattern still works for TTS with the corrected model ids was not smoke-tested this pass - only the id strings were fixed, since migrating the whole request/response shape is a materially bigger change than "fix the model suffix." Recommend a live smoke test before the next feature work touches this adapter; migrate to `interactions.create` if it 404s.
11. **OPEN - Nano Banana (`image/nanobanana.ts`) endpoint pattern.** Same shape of finding as #10's open item: current Gemini docs exclusively show the new `POST /v1beta/interactions` API (confirmed request shape: `{model, input:[{type:'text',text}], response_format:{type:'image', aspect_ratio, image_size}}`; confirmed response shape: `{id, status, steps:[{type:'model_output', content:[{type:'image', data, mime_type}]}]}`) for `gemini-3.1-flash-image`/`gemini-3-pro-image`. The adapter still uses the legacy `generateContent` + `responseModalities: ['TEXT','IMAGE']` pattern. Not migrated this pass: there's no confirmation the legacy path is actually broken for the older `gemini-2.5-flash-image` catalog option, and switching wholesale risks a regression there without a live smoke test. Left as a documented follow-up rather than risked.
12. **RE-VERIFIED, NO CHANGE - Cartesia `sonic-3`.** Context7 (`/cartesia-ai/docs`) confirms `sonic-3` is a real, currently-documented model (used directly in Cartesia's own Twilio integration example), not a stale/invalid id as the original audit suspected. `sonic-3.5` is now the recommended flagship, but `sonic-2`/`sonic-3` remain valid and supported for compatibility per Cartesia's own "Older Models" doc. No catalog change made.
13. **OPEN, documentation only - Groq/Gemini exact model rosters.** Context7 still doesn't enumerate a full current model list for either family. This pass confirmed `gemini-3.1-flash-lite` (GA as of the 2026-05-07 changelog) and `gemini-3.5-flash` (used in current Interactions API examples) are real; `gemini-3-flash` (non-`.1`, non-`.5`) and both `gemma-4-*` catalog ids were not independently confirmed or denied. No catalog change made without stronger evidence either way.
14. **OPEN - OpenRouter (`script/openrouter.ts`) possible stale header name and unchecked `choice.error` field.** Not in this pass's fix scope (not part of the prioritized list); still open from the original audit. Adapter sends `X-Title`; current docs show `X-OpenRouter-Title`. `res.choices[0]?.message?.content ?? ''` doesn't check for an embedded `choice.error` on partial/routing failures.
15. **OPEN - fal.ai image/video adapters mutate global SDK config (`fal.config()`).** Not in this pass's fix scope. Still safe today only because `server/worker/loop.ts` processes one job at a time; becomes a real key-leak risk if the worker is ever made concurrent.
16. **FIXED (docs) - stale doc comment.** `docs-site/content/2.backend/3.providers.md`'s claim about which image providers return bytes vs. a URL was updated again in this pass now that OpenAI Images also returns bytes (see #1): the image category now correctly lists Stability, OpenAI Images, Nano Banana, and Hugging Face Image as byte-returning, with fal, Ideogram, Together, and Replicate returning a URL. The equivalent code comment in `server/worker/providers/types.ts` was left as-is (a code-comment-only nit, not corrected here since it wasn't blocking any behavior).

Missing test coverage noticed in passing, not added in this pass (out of scope - this was a bug-fix pass, not a coverage pass): still no `groq.script.test.ts`, no `mistral.script.test.ts`.

## Usage/cost metadata inventory (for card 134)

No adapter today captures usage/cost metadata; every `*Result` type only carries the generated content. This audit inventoried what's actually available in each provider's response, for a future usage-logging feature (see [Planned: Retry, Usage Logging, Team Access](/guides/planned-retry-usage-team-access)):

- **Richest single source: OpenRouter.** Returns real dollar `cost` in-band per response (`cost`, `cost_details.upstream_inference_cost`, plus full token breakdowns including cached/reasoning/audio/image token splits). Best anchor for validating any cost-estimation model built for other providers.
- **Token-based (script):** Anthropic (`usage.input_tokens`/`output_tokens`, plus cache read/write counts), OpenAI (`usage.prompt_tokens`/`completion_tokens`, plus cached/reasoning token detail), Gemini (`usageMetadata`, including `thoughtsTokenCount`), Groq (standard OpenAI-shape `usage` plus Groq-specific `x_groq.usage` timing fields), Mistral (`UsageInfo.promptTokens`/`completionTokens`), Hugging Face script (OpenAI-compatible `usage` by convention, not independently reconfirmed).
- **Character/unit-based (audio):** ElevenLabs, PlayHT, Cartesia, and Fish Audio all bill primarily by character count of input text (industry-standard TTS billing; not all individually re-verified via Context7 pricing pages this pass). Hugging Face Inference (serverless) billing is compute-time/credit based, not character-count based, so a unified usage schema needs a units-agnostic shape (see the `units: jsonb` recommendation in the planning doc) rather than assuming "characters" applies everywhere.
- **Image:** OpenAI Images returns a `usage` (token) object; Gemini/Nano Banana returns `usageMetadata`; Replicate exposes `metrics.predict_time` per prediction. fal, Stability, Ideogram, Together AI, Hugging Face Image: no usage metadata observed in adapter responses this pass.
- **Video (most expensive category, least metered in-band):** none of the 8 video adapters surface cost/resolution/duration-actually-used metadata in the parsed result today, even though Runway, Kling, MiniMax, Replicate, and fal all bill per-second/per-resolution behind the scenes. A future usage-logging pass will likely need each adapter to also read and return provider-side metering fields, not just the generated asset.

## Not verified / remaining gaps

- Groq and Gemini script model rosters: Context7 coverage didn't enumerate a full current model list for either; the catalog's specific IDs (`llama-3.3-70b-versatile`, `llama-3.1-8b-instant`, `gemini-3-flash`, both `gemma-4-*` entries) are plausible but not independently confirmed against a live model-list endpoint. `gemini-3.1-flash-lite` and `gemini-3.5-flash` were confirmed real this pass.
- Runway: no dedicated Context7 library was indexed; findings rely on web search against Runway's own docs rather than Context7's structured retrieval.
- Gemini TTS and Nano Banana: model ids/endpoint host confirmed reachable in principle, but no live smoke test was run against either adapter's actual request/response parsing this pass - see issues #10 and #11.
- Fish Audio's `prosody.speed` param name remains unconfirmed (docs inconsistent on request/response shape generally) - not in this pass's scope.
- OpenRouter's `X-Title` vs `X-OpenRouter-Title` header and unchecked `choice.error` field - not in this pass's scope, see issue #14.
- `fal.config()` global-state concurrency risk - not in this pass's scope, see issue #15.
