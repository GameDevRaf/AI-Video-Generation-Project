Every HTTP endpoint under `server/api/`. Nuxt maps files to URLs: `server/api/scenes/index.get.ts` = `GET /api/scenes`, `[id].patch.ts` = `PATCH /api/scenes/:id`.

**Shared pattern** - nearly every route starts identically:

```ts
export default defineEventHandler(async (event) => {
  const user = await serverSupabaseUser(event)                    // read auth cookie
  if (!user) throw createError({ statusCode: 401, message: 'Unauthorized' })
  const supabase = await serverSupabaseClient(event)              // user-scoped client (RLS applies)
  // …verify project ownership if a projectId is involved → 403 if not owned…
  // …do the work, return plain data (Nuxt serializes to JSON)…
})
```

Auto-imported helpers used everywhere: `readBody<T>(event)` (parse JSON body), `getQuery(event)` (query params), `getRouterParam(event, 'id')` (path params), `createError({statusCode, message})` (throw an HTTP error).

Common error codes: `401` not signed in · `400` missing/invalid params · `403` resource not owned (deliberately phrased "not found" to avoid leaking existence) · `404` no such row · `500` database error.

## Jobs

### `POST /api/jobs` - create (or reuse) a job
Body: `{ projectId: string, type: JobType, input?: object, provider?: string, model?: string }`.
Verifies project ownership. Video inputs should use `image_path` for an internal first frame; the route verifies that path belongs to an image output in the project before enqueueing. **Deduplicates**: if a `queued`/`processing` job with the same project + type + `input.scene_id` (or both scene-less) exists, returns it instead of inserting. Inserts with `status: 'queued'`.
Returns: the job row (`DbJob`).

Ownership check + dedupe + insert live in the shared `createJobWithDedup(supabase, userId, params)` helper (`server/utils/jobCreation.ts`), reused by the retry route below so both paths dedupe identically.

### `GET /api/jobs?projectId=&type=` - list jobs
Both query params optional filters; always filtered to the current user; newest first.
Returns: `DbJob[]`.

### `GET /api/jobs/:id` - one job **with outputs**
Returns: `DbJob & { job_outputs: DbJobOutput[] }` - this is the polling endpoint used by `useJobPoller`. 404 if not found/not owned.

### `POST /api/jobs/:id/retry` - manually retry a failed job
Body (all optional): `{ provider?: string, model?: string, input?: object }` - overrides for the failed job's own values (e.g. retry with a different provider after adding its key). Omit the body entirely to re-run the exact failed config.

Verifies the job is owned by the caller (404 if not) and is currently `status: 'failed'` (400 otherwise - see `getRetryableJob` in `server/utils/jobCreation.ts`). **Creates a new job row** with the failed job's `project_id`/`type`/`input`/`provider`/`model` (or the given overrides) via `createJobWithDedup` - it does not mutate the failed row, so the failed attempt stays in history. Because dedupe only ever matches `queued`/`processing` jobs, a `failed` row can never block its own retry.
Returns: the new job row (`DbJob`), same shape as `POST /api/jobs`. The worker picks it up on its next 3s tick.

## Projects

### `GET /api/projects` - list with settings
Returns: `(DbProject & { project_settings })[]`, newest-updated first.

### `POST /api/projects` - create
Body: `{ name: string, description?: string }` (name required/trimmed). Also inserts a default `project_settings` row.
Returns: the project.

### `GET /api/projects/:id` - one with settings. 404 if not owned.

### `PATCH /api/projects/:id` - update
Body: any of `{ name, description, status, current_stage }`. Used by the store's `setStage`.

### `DELETE /api/projects/:id` - delete (cascades to jobs/scenes/outputs via FK). Returns `{ success: true }`.

### `PATCH /api/projects/:id/settings` - upsert project settings
Body: any subset of `prompt_edit_mode`, `default_<script|image|audio|video>_provider`, `default_<script|image|audio|video|music>_model`, `timeline_density`, `skip_video_gen`, `target_duration_seconds` (server-clamped to `VIDEO_FORMAT.maxDuration`). Upserts on `project_id`.
Returns: the settings row.

## Scenes

### `GET /api/scenes?projectId=` - list ordered by `order_index`. Ownership-checked.

### `POST /api/scenes` - create an empty scene
Body: `{ projectId }`. Appends at the end (`scene_index = order_index = count`), `script_text: ''`, `duration: 5`.
Returns: the new scene.

### `PATCH /api/scenes/:id` - update fields
Body: any of `{ script_text, title, duration, start_time, end_time, order_index }`. Ownership verified via a join to `projects` (scene → project → user).

### `DELETE /api/scenes/:id` - delete one scene. Same join-based ownership check. Returns `{ success: true }`.

### `POST /api/scenes/reorder` - bulk position/timestamp update
Body: `{ projectId, scenes: [{ id, order_index, start_time, end_time, duration }] }`. Runs the per-scene updates in parallel (`Promise.all`) since Supabase lacks bulk update. The client (`useScenes.recalcTimestamps`) computes the values; this route just persists them.

## Provider keys

### `GET /api/provider/keys` - list key **metadata**
Returns: `{ id, provider, key_name, is_active, created_at }[]`. **Never returns the secret.**

### `POST /api/provider/keys` - save a key
Body: `{ provider: string, secret: string, keyName?: string }`. Encrypts `secret` with AES-256-GCM (`server/utils/crypto.ts`) before insert. Callers must pass the **key** provider id (`keyProviderId ?? id` - the ModelSelector does this).
Returns: metadata (no secret).

### `DELETE /api/provider/keys/:id` - delete a key. Returns `{ success: true }`.

## User settings

### `GET /api/settings` - current user's row from `user_settings`; **auto-creates** a defaults row on first call (detects Postgres "no rows" error `PGRST116`).

### `PATCH /api/settings` - upsert
Body: any subset of `prompt_edit_mode`, `default_<script|image|audio|video>_provider`, `default_audio_voice_id`, `default_<image|video|audio|music>_model`.

## Stage data (read endpoints powering the workspace)

All take `?projectId=`, all ownership-check, all implement **latest-wins** dedup (newest `job_outputs` row per scene label).

### `GET /api/script`
Reconstructs script state for a reopened project: script text from the newest `scene_split` job's input; idea + tone from the newest `script` job's input.
Returns: `{ text, idea, tone }` (each nullable).

### `GET /api/image-prompts`
Latest `image_prompt_scene_*` output per scene.
Returns: `{ sceneId, outputId, prompt }[]` (`outputId` is needed to PATCH edits back).

### `PATCH /api/image-prompts/:outputId`
Body: `{ prompt: string }`. Overwrites `metadata.content` of that output row. Ownership: reads the row via **admin client** (RLS blocks plain reads by id), verifies the user owns `output.project_id` via the user client, then updates via admin client (RLS has no UPDATE policy on job_outputs).

### `GET /api/video-prompts` / `PATCH /api/video-prompts/:outputId`
Mirrors of the image-prompt pair, for `video_prompt_scene_*` labels.

### `GET /api/images`
Latest `scene_image_*` file output per scene.
Returns: `{ sceneId, url, storage_path, generationPrompt, createdAt }[]` - `url` is a one-hour signed URL, while `storage_path` is the durable identifier used by queued jobs. `generationPrompt` is the prompt stored in metadata at generation time (drives the "stale image" dot), and `createdAt` lets later UI stages detect when an export-relevant asset is newer than the latest MP4.

### `GET /api/videos`
Latest `scene_video_*` file output per scene.
Returns: `{ sceneId, url, generationPrompt, createdAt }[]` - mirrors `GET /api/images`, but for scene videos.

### `GET /api/audio`
The newest `voice_track` output.
Returns: `{ url, sceneSnapshot, createdAt }` or `null`. `sceneSnapshot` is the scene text captured when the track was combined - the AudioStage compares it against current scenes to show the staleness dot. `createdAt` is used by the export UI to tell whether audio changed after the last MP4 was exported.

### `POST /api/audio/combine`
Body: `{ projectId }`. Server-side ffmpeg: downloads the latest `scene_audio_*` for **every** scene (422 if any missing), concatenates in scene order, re-encodes to 44.1 kHz stereo MP3, uploads to Storage, creates a synthetic completed `audio` job (provider `internal/concat`) so the FK holds, and inserts a `voice_track` output whose metadata includes `scene_snapshot`.
Returns: `{ url }`.

## Uploads

### `POST /api/uploads/media` - user uploads their own media
Multipart form: `projectId`, `type` (`image|audio|video`), `file`, `sceneId` (required for image/video, absent for audio).
Validates mime type against an allow-list (`server/utils/mediaUpload.ts`). **Videos are transcoded to MP4** (H.264/AAC) via ffmpeg before storing, so any container (webm/mov/avi/mkv) becomes export-compatible. Creates a synthetic completed job (provider `upload`), a `job_outputs` row with the standard scene label (so uploads participate in latest-wins exactly like generated media), and for image/video a `scene_assets` link row.
Returns: `{ url, outputId, jobId, type, sceneId }`.

## Exports

### `GET /api/exports?projectId=`
Export history joined with job status: `(exports & { jobs: { status, output_summary } })[]`, newest first.
