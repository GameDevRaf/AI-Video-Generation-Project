# Composables

Reusable stateful functions in `app/composables/`, auto-imported everywhere. Unlike stores, **each call creates its own state** - two components calling `useScenes(id)` have independent scene lists (they stay consistent because both re-fetch from the server).

A recurring parameter: `projectId: MaybeRef<string>` - accepts a plain string or a `ref`; internally read with `toValue(projectId)`. Callers pass `toRef(props, 'projectId')` so the composable stays correct if the prop changes.

---

## useJobPoller.ts - `useJobPoller()`

The standard way to run **one job at a time** and watch it finish. Used by every stage for single-job actions.

**Returns**
| Name | Type | Meaning |
|---|---|---|
| `job` | `Ref<JobWithOutputs \| null>` | Latest polled job, **including `job_outputs`** - components read results straight off this |
| `polling` | `Ref<boolean>` | Interval active |
| `isRunning` | `Computed<boolean>` | starting ∨ polling ∨ status queued/processing - bind buttons' `:disabled` to this |
| `isDone` / `isFailed` | `Computed<boolean>` | Terminal status checks |
| `error` | `Ref<string \| null>` | Submission/polling error |

### `startJob(projectId, type, input): Promise<JobWithOutputs | undefined>`
Guards against concurrent calls (returns immediately if one is running - double-click protection layered on top of the server-side dedup), POSTs `/api/jobs`, then polls `GET /api/jobs/:id` every 2 s (`useIntervalFn` from VueUse) until `completed`/`failed`.

### `reset(): void`
Stop polling, clear all state.

**Typical usage**: `watch(job, j => { if (j?.status === 'completed') refreshData() })`.

## useProjects.ts - `useProjects()`

Dashboard project list.

| Returns | Meaning |
|---|---|
| `projects: Ref<ProjectWithSettings[]>` | The list |

| `fetchProjects()` | `GET /api/projects` |
| `createProject(name, description?)` | `POST /api/projects`, then re-fetches the list; returns the new project |

## useScenes.ts - `useScenes(projectId)`

Scene list + editing + the **timestamp recalculation** logic that keeps `start_time`/`end_time` consistent whenever order or durations change.

**State**: `scenes: Ref<DbScene[]>`, `loading`, `error`, computed `totalDuration` (sum of durations).

### `fetchScenes(): Promise<void>`
`GET /api/scenes?projectId=` into `scenes` (ordered by `order_index`).

### `recalcTimestamps(list: DbScene[]): DbScene[]` *(pure)*
Walks the list in order, assigning `order_index = i` and cumulative `start_time`/`end_time` from durations (missing duration → 5 s). Returns a **new** array; does not touch state or the server. Exported so AudioStage can reuse it after audio generation changes durations.

### `persistTimestamps(list): Promise<void>`
`POST /api/scenes/reorder` with each scene's `{ id, order_index, start_time, end_time, duration }`. Always call this after `recalcTimestamps`.

### `updateScene(id, patch): Promise<void>`
Optimistic local merge. If `duration` changed → full recalc + persist of **all** scenes; otherwise a single `PATCH /api/scenes/:id`. `patch` may contain `script_text`, `title`, `duration`.

### `moveScene(id, direction: 'up' | 'down'): Promise<void>`
Swap with the neighbor, recalc, persist. No-op at list edges.

### `deleteScene(id): Promise<void>`
`DELETE` on the server first, then remove locally, recalc + persist the remainder.

### `createScene(): Promise<DbScene>`
`POST /api/scenes` (empty scene appended server-side), append locally, recalc + persist. Returns the new scene.

## useImageStage.ts - `useImageStage(projectId)`

Owns the Image tab's data: prompts and generated images, both keyed by scene id.

**State** (all `Ref<Map<string, ...>>`):
- `prompts`: sceneId → `{ sceneId, outputId, prompt }` (outputId needed for saving edits)
- `images`: sceneId → image URL
- `generationPrompts`: sceneId → the prompt used when the current image was generated (staleness detection)
- `loading`

| Function | Behavior |
|---|---|
| `fetchPrompts()` | `GET /api/image-prompts` → `prompts` |
| `fetchImages()` | `GET /api/images` → `images` + `generationPrompts` |
| `savePrompt(sceneId, newText)` | Optimistic map update + `PATCH /api/image-prompts/:outputId` |
| `setPromptsFromJob(outputs)` | Replace the prompt map from a completed job's parsed outputs |
| `getPrompt(scene)` / `hasPrompt(scene)` / `getImage(scene)` / `getGenerationPrompt(scene)` | Per-scene readers (take a `DbScene`) |

---

## useVideoStage.ts - `useVideoStage(projectId)`

Mirror of useImageStage for the Video tab (`/api/video-prompts`, `/api/videos`). Differences: per-scene readers take a **sceneId string** (not a scene object), and it adds `hasAnyVideo` / `hasAnyPrompt` computed flags used to label buttons ("Generate" vs "Regenerate").

---

## useAudioStage.ts - `useAudioStage(projectId)`

Voice settings + the existing voice track. Also exports module-level constants:

- `VOICES: Record<'elevenlabs' | 'openai_tts', VoiceOption[]>` - static voice catalog (id, name, gender). Only these two providers have UI voice pickers; other TTS providers use handler-side defaults.
- Interfaces `VoiceOption`, `AudioSettings`.

**State**
| Name | Meaning |
|---|---|
| `settings: Ref<AudioSettings>` | `{ provider, voiceId, speed, stability, similarityBoost }` (stability/similarity are ElevenLabs-only) |
| `audioUrl: Ref<string \| null>` | Latest `voice_track` URL |
| `generationSnapshot` | Scene text snapshot stored when the track was combined - compared with current scenes to show the "stale audio" dot |
| `currentVoices` *(computed)* | Voice list for the selected provider |

| Function | Behavior |
|---|---|
| `fetchExistingAudio()` | `GET /api/audio` → `audioUrl` + `generationSnapshot` |
| `setAudioUrl(url)` | Direct setter (used after uploads) |
| `setProvider(p)` | Switch provider and reset `voiceId` to that provider's first voice |

Note: the actual generation orchestration (one job per scene, polling, combine call) lives in `AudioStage.vue`, not here - see [components.md](/frontend/components#audiostagevue).
