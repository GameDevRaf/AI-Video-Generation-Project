---
title: "Pages, Layouts and Routing"
description: "How Nuxt pages, layouts, middleware, and routes fit together."
---

Nuxt turns files in `app/pages/` into URLs automatically. Pages choose a **layout** (shared chrome) via `definePageMeta({ layout: '...' })` and can require login via `middleware: 'auth'`.

## Middleware

### `app/middleware/auth.ts`
Runs before entering any page that declares `middleware: 'auth'`. Checks `useSupabaseUser()`; redirects to `/auth/login` if not signed in. (Separately, `nuxt.config.ts` → `supabase.redirectOptions` gives the Supabase module its own redirect rules with an exclude list for public pages.)

## Layouts

| Layout | Used by | Contains |
|---|---|---|
| `default.vue` | landing | Bare dark background wrapper |
| `dashboard.vue` | dashboard, settings | Top nav (logo, Projects, Settings), sign-out button |
| `workspace.vue` | workspace page (applied manually via `<NuxtLayout name="workspace">`) | Editor chrome: back-to-dashboard link, project name (prop `projectName`), and three **slots** the page fills - `#tabs` (stage tab bar), `#model-selector` (provider picker), `#timeline` (bottom bar) |

## Pages

### `/` - `pages/index.vue`
Public landing page: headline + links to signup/login. Redirects nothing; purely informational.

### `/auth/login` - `pages/auth/login.vue`
Email/password form. On submit calls `supabase.auth.signInWithPassword(...)` directly from the browser (auth talks straight to Supabase, not to our API), then routes to `/dashboard`. Local state: `form { email, password }`, `loading`, `error`.

### `/auth/signup` - `pages/auth/signup.vue`
Same shape with `supabase.auth.signUp(...)`; shows a "check your email" success state. Email confirmation lands on `/confirm`.

### `/confirm` - `pages/confirm.vue`
Target of the Supabase email-confirmation redirect (configured in `nuxt.config.ts`). Immediately forwards to `/dashboard`.

### `/dashboard` - `pages/dashboard.vue` *(auth, dashboard layout)*
Project list. Uses `useProjects()`; renders a `<ProjectCard>` grid; "New project" opens `<CreateProjectModal>`; card delete asks `confirm()` then `deleteProject`. On creation navigates to `/workspace/<id>`.

### `/settings` - `pages/settings.vue` *(auth, dashboard layout)*
Two sections:
1. **Default providers** - one `<SettingsProviderRow>` per category (script/image/audio/video) writing `default_<cat>_provider` to `PATCH /api/settings` (user-level defaults; projects can override).
2. **API keys** - list keys from `GET /api/provider/keys`, add (`POST`, encrypted server-side), delete. Also the prompt-edit-mode preference.

### `/workspace/:projectId` - `pages/workspace/[projectId].vue` *(auth, workspace layout - the heart of the UI)*

Orchestrates the whole editing experience. Responsibilities:

- **Tabs**: local `activeTab` (`script | image | audio | video`) rendered by `<WorkspaceStageTabs>`; tabs unlock based on `projectStore.currentStage`. Switching tabs slides content left/right (CSS transitions on `.tab-panel`).
- **Deferred scene-order apply**: when the user leaves the Script tab, the page flushes any pending reorder tracked by `useSceneOrderSync`. If the final local order differs from the last saved order, it persists the new `order_index` values once and then calls `POST /api/audio/combine` so the combined `voice_track` matches the new scene order without re-running TTS jobs. The same flush runs in `onBeforeRouteLeave`, so leaving `/workspace/:projectId` applies the pending order before navigation completes.
- **Stage components**: renders the matching `<Stages*Stage>` for the active tab. The Script tab also shows `<StagesSceneSplitStage>` once the project is at/past `scene_split`; the Video tab shows `<StagesExportStage>` once at `export`.
- **Stage progression**: each stage emits `done` → handlers here call `projectStore.setStage(next)` and switch tabs (`onScriptDone → 'scene_split'`, `onSceneDone → 'image'`, `onImageDone → 'audio'`, `onAudioDone → 'video'`, `onVideoDone → 'export'` + scroll to export).
- **On mount (restore)**: loads the project into the store; if past the script stage, fetches the locked script text from `GET /api/script` into the workspace store (AudioStage and SceneSplitStage need it); opens the tab matching the saved stage; loads which providers have saved keys (`savedProviderIds`) for the model selector badges.
- **Model selector wiring**: `currentProviderId` maps the active tab to the project setting field (`STAGE_PROVIDER_FIELD`); `onProviderChanged(providerId, modelId)` persists both `default_<tab>_provider` and `default_<tab>_model` via `projectStore.updateSettings`.
- **Cleanup on unmount**: `jobsStore.cancelAll()` (stop pollers) + `projectStore.reset()`.

Data ownership note: this page deliberately owns *no* stage data - scenes, prompts, images etc. are owned by each stage component through composables. The page only owns navigation, provider selection, and restore logic.
