---
title: "Pinia Stores"
description: "State management responsibilities and actions exposed by each store."
---

Global reactive state in `app/stores/`. A store is an app-wide singleton: every component calling `useProjectStore()` gets the **same** instance. Use a store when many components need the data; use a composable when one stage owns it.

All three use the "setup store" style: `defineStore('name', () => { ...refs & functions...; return {...} })`.

---

## project.ts - `useProjectStore()`

The currently open project + its settings + pipeline stage. Loaded once by the workspace page; read by every stage component.

**State**
| Name | Type | Meaning |
|---|---|---|
| `currentProject` | `DbProject \| null` | The loaded project row |
| `settings` | `DbProjectSettings \| null` | Its `project_settings` row (providers, models, skip_video_gen, target duration…) |
| `loading` / `error` | `boolean` / `string \| null` | Load state |

**Computed**
- `currentStage: string` - `currentProject.current_stage`, defaulting `'script'`. Drives tab locking and which sub-stages render.
- `projectId: string | null`.

**Actions**
### `loadProject(id: string): Promise<void>`
Fetches `GET /api/projects/:id` (project + settings) into state. Errors land in `error`, never throw.

### `setStage(stage: string): Promise<void>`
Optimistically sets `current_stage` locally, then persists via `PATCH /api/projects/:id`. Called by the workspace page's stage-done handlers. Valid values: `script, scene_split, image, audio, video, export`.

### `updateSettings(partial: Partial<DbProjectSettings>): Promise<void>`
Optimistic merge into `settings`, then `PATCH /api/projects/:id/settings`. **On failure it rolls the local state back** and re-throws - callers (e.g. the Skip Video Gen toggle) catch and show an error. This rollback matters: without it the UI would show a setting the DB doesn't have.

### `reset(): void`
Clears everything. Called when leaving the workspace.

## workspace.ts - `useWorkspaceStore()`

Small cross-component UI state for the workspace session. Nothing here persists to the DB directly.

**State**
| Name | Type | Meaning |
|---|---|---|
| `projectId` | `string \| null` | Set on workspace mount |
| `activeScriptText` | `string \| null` | The locked-in script. Written when the user clicks "Use this script" (or restored from `GET /api/script`); read by SceneSplitStage (display) and ScriptStage (locked summary) |
| `activeScriptOutputId` | `string \| null` | Which job output the text came from |
| `playbackTime` / `isPlaying` / `isTimelineExpanded` | number/bool/bool | Timeline UI state (timeline is currently a visual placeholder) |

**Actions**: `setProject(id)`, `setActiveScript(text, outputId?)`, `clearActiveScript()`, `reset()` - all trivial setters.

## jobs.ts - `useJobsStore()`

Tracks **multiple jobs simultaneously** - used by the bulk "Generate all images/videos" flows (single-job flows use the `useJobPoller` composable instead). Holds a reactive job map plus non-reactive interval handles.

**State**
- `activeJobs: Record<string, DbJob>` - jobId → latest known job row (reactive).
- `pollers: Map<string, interval>` - private, non-reactive.

**Queries**
### `getJob(id): DbJob | undefined`
### `getLatestByType(projectId, type): DbJob | undefined`
Newest tracked job of a type for a project (sorts by `created_at`).
### `isRunning(projectId, type): boolean`
True if that latest job is `processing`/`queued`/`retrying`.

**Actions**
### `track(job: DbJob): void`
Insert/replace the job in the map (immutable-style replace so Vue notices).

### `createJob(projectId, type, input): Promise<DbJob>`
`POST /api/jobs` (server may return an existing duplicate - see dedup), tracks it, returns it. Note: unlike `useJobPoller.startJob`, provider/model must be passed inside `input` here.

### `startPolling(id, onDone?): void`
Starts a 2-second interval fetching `GET /api/jobs/:id`; keeps `track()`ing updates; on terminal status clears the interval and calls `onDone(job)`. No-op if already polling that id. Transient fetch errors are swallowed (retry next tick).

### `cancelPoll(id)` / `cancelAll()`
Stop one poller / stop everything and clear the map. `cancelAll` runs on workspace unmount - **forgetting this would leak timers** that keep fetching after leaving the page.

**Usage pattern (bulk generation)** - from VideoStage:
```ts
const job = await jobsStore.createJob(projectId, 'video', { scene_id, prompt, ... })
jobsStore.startPolling(job.id, (finished) => {
  if (finished.status === 'completed') refreshVideos()
  settleOne()   // component-level countdown to re-enable the button
})
```
