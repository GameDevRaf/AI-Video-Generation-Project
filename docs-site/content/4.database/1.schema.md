Postgres, hosted on Supabase. Schema is defined by the numbered SQL files in `supabase/migrations/` (run in order, never edit an applied one - add a new number). TypeScript mirrors of every row live in `app/types/database.types.ts` (`DbJob`, `DbScene`, …) - **keep them in sync when you migrate**.

## Entity relationships

```
auth.users (Supabase-managed)
    │ 1:1 (trigger-created)
    ▼
  users ──1:N── projects ──1:1── project_settings
    │               │
    │               ├──1:N── jobs ──1:N── job_outputs
    │               │                        ▲
    │               ├──1:N── scenes ──1:N── scene_assets (links a scene to an output)
    │               └──1:N── exports (also N:1 → jobs)
    ├──1:N── api_keys
    ├──1:1── user_settings
    └──1:N── connected_accounts (future publish feature - unused)
```

All FKs cascade on delete from projects/users, so deleting a project cleans up everything under it (Storage files are *not* auto-deleted, only the DB rows).

## Tables

### users
Profile row mirroring `auth.users`, auto-created by the `on_auth_user_created` trigger (`handle_new_user()` function) on signup. Columns: `id (=auth uid)`, `username`, `email`, `avatar_url`, timestamps.

### projects
| Column | Type | Notes |
|---|---|---|
| `id` | uuid PK | |
| `user_id` | uuid FK→users | owner |
| `name`, `description` | text | |
| `status` | text | `'active'` default; export sets `'completed'` |
| `current_stage` | text | `script → scene_split → image → audio → video → export`; drives tab locking |

### jobs - the queue
| Column | Type | Notes |
|---|---|---|
| `type` | text | `script, scene_split, image_prompt, image, audio, video_prompt, video, music, export, publish` |
| `status` | text | `queued, processing, waiting_on_provider, completed, failed, retrying` |
| `provider`, `model` | text? | which AI service/model (null → resolved from settings at run time) |
| `input` | jsonb | job-type-specific parameters (shapes documented in [job-handlers.md](/backend/job-handlers)) |
| `output_summary` | jsonb | small result summary written on completion |
| `error_message` | text? | last failure |
| `retry_count` | int | 0–3 |
| `started_at`, `completed_at` | timestamptz? | |

Indexes: `(project_id, status)` and `(status, created_at)` - the latter is what the worker's claim query uses.

### job_outputs - everything generated
| Column | Type | Notes |
|---|---|---|
| `job_id`, `project_id` | uuid FK | project_id denormalized so readers don't need a join |
| `type` | text | `text, image, audio, video, music, json, file` |
| `label` | text? | **the addressing scheme** - see [conventions.md](/database/conventions) |
| `storage_url`, `storage_path` | text? | public URL + bucket path (file outputs only) |
| `mime_type` | text? | |
| `metadata` | jsonb? | text content (`{content}`), generation prompt (`{prompt}`), audio duration, export manifest, scene snapshots… |

Insert-only in practice (except prompt edits, which PATCH `metadata.content`). Regenerations add rows; readers take the newest per label.

### scenes
| Column | Type | Notes |
|---|---|---|
| `project_id` | uuid FK | |
| `job_id` | uuid FK? | the scene_split job that created it (null for manually added) |
| `scene_index` | int | index at creation time (historical) |
| `order_index` | int | **current** position - always use this for ordering |
| `title` | text? | short label |
| `script_text` | text | the words spoken in this scene |
| `start_time`, `end_time`, `duration` | numeric? | seconds; recalculated client-side (`useScenes.recalcTimestamps`) whenever order/durations change; audio generation overwrites `duration` with the real spoken length |

### scene_assets
Link table: `scene_id` → `job_output_id` with `asset_type` and `role` (`first_frame, voice, generated_video, music_bed`). Currently written by the **upload** endpoint only; generated media is found via labels instead. Read-path code does not depend on it yet.

### project_settings (1:1 with projects, created on project creation)
| Column | Added in | Meaning |
|---|---|---|
| `prompt_edit_mode` | 001 | `before_generation` / `after_generation` (workflow hint badge) |
| `default_image_model`, `default_audio_model`, `default_video_model`, `default_music_model` | 001 | per-project model choices |
| `timeline_density` | 001 | unused placeholder |
| `default_script_provider`, `default_image_provider`, `default_audio_provider`, `default_video_provider` | 004 | per-project provider overrides (null = fall back to user_settings) |
| `skip_video_gen` | 006 | export images-as-slideshow mode |
| `target_duration_seconds` | 007 | script length target (clamped to 180) |
| `default_script_model` | 008 | completes the 004 set |

### user_settings (1:1 with users, auto-created by `GET /api/settings`)
Account-wide defaults: `default_script_provider ('anthropic')`, `default_image_provider ('fal')`, `default_video_provider ('runway')`, `default_audio_provider`, `default_audio_voice_id`, `prompt_edit_mode`, plus legacy model columns. Resolution order everywhere: **job input → job row → project_settings → user_settings → hardcoded default**.

### api_keys
`provider` (the **key** provider id - shared-key providers store under e.g. `gemini`), `key_name?`, `encrypted_secret` (AES-256-GCM `iv:tag:ciphertext`), `is_active`. Multiple keys per provider allowed; the newest active one wins.

### exports
One row per completed export: `project_id`, `job_id`, `export_type ('mp4')`, `storage_url`, `metadata.manifest` (scene list, durations, URLs, mode).

### connected_accounts
Scaffolding for a future social-publish feature. No code writes to it.

## Row-Level Security (RLS)

Every table has RLS enabled with owner-only policies (`auth.uid() = user_id`, or joined through projects for child tables). Practical implications:

- API routes using the user client physically **cannot** read/write another user's rows.
- `job_outputs` has **no UPDATE/DELETE policies** - that's why prompt-edit routes use the admin client for the write (after verifying ownership with the user client).
- The worker's `adminSupabase` bypasses all of it (service role).

## Storage

One public bucket **`assets`** (created in migration 005). Path convention: `<projectId>/<images|audio|videos|exports>/<file>`. URLs stored in `job_outputs.storage_url` are public - anyone with the URL can fetch the file (acceptable for now; revisit for private projects).

## Making schema changes

1. Add `supabase/migrations/009_<name>.sql` (next number).
2. Run it in the Supabase SQL editor.
3. Update the matching interface in `app/types/database.types.ts`.
4. If it's a settings column: add it to the PATCH route's body type (`server/api/settings/index.patch.ts` or `projects/[id]/settings.patch.ts`) - unlisted fields are still passed through, but the typed body documents the contract.
5. Update this doc's table above.
