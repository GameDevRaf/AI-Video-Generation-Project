The traps that actually bite in this codebase - for humans and AI assistants alike. Skim this before every non-trivial change.

## TypeScript strictness: `noUncheckedIndexedAccess`

This project's `tsconfig` makes **every index access possibly-undefined**:

```ts
const first = items[0]          // type: T | undefined  ← even if you KNOW it's non-empty
const val = record[key]         // V | undefined
const head = s.split(':')[0]    // string | undefined
```

Fixes, in order of preference:

```ts
const first = items[0] ?? fallback              // provide a default
if (items.length) { use(items[0]!) }            // ! only AFTER a real bounds check
const [a, b] = pair as [string, string]         // tuple cast when the shape is guaranteed
```

Typecheck with `npx nuxi typecheck` after changes - the dev server does **not** fail on type errors, so they hide until you check.

## Import path rules (three different worlds)

| From | To | Use |
|---|---|---|
| `app/**` | `app/**` | `~/` alias (`~/types/database.types`) or rely on auto-import |
| `server/api/**` | `supabase-server.ts` | `~~/supabase-server` (project root alias) |
| `server/worker/**` | anything | **relative paths only** (`'../../../app/types/database.types'`) - the standalone worker runs under `tsx`, outside Nuxt, and resolves no aliases |
| anywhere | `shared/**` | **relative paths only**, same reason |

Getting this wrong works in the dev server and then crashes `npm run worker` (or vice versa).

## Auto-imports cut both ways

`ref`, `computed`, `watch`, composables, `defineEventHandler`, `readBody`… are injected. Two traps:
- Don't manually import them with wrong paths (e.g. `import { ref } from 'vue'` is fine, but importing a composable from a guessed path breaks the auto-registration).
- A new file in `app/composables/` or `server/utils/` is auto-importable **by its exported name** - name collisions across files fail confusingly. Keep exported names unique.

## `.value` or not

`ref`s need `.value` in `<script>`, none in `<template>`. A composable returning `{ scenes }` where `scenes` is a ref: `scenes.value.length` in script, `scenes.length` in template. Forgetting `.value` in script code compares/assigns the ref object itself - TS usually catches it, but not in untyped spots.

Also: passing a prop into a composable? Use `toRef(props, 'projectId')`, not `props.projectId` - the latter freezes the current value.

## Two Supabase clients - don't mix them up

- `serverSupabaseClient(event)` = the user, RLS enforced. Default choice in API routes.
- `adminSupabase` = god mode, RLS bypassed. Worker + rare route escapes only, always after an ownership check.

Using admin where user would do removes a safety net; using user in the worker fails (no cookies).

## The worker is a separate process

- Changing worker/handler/provider code? The **standalone worker** (`worker:watch`) hot-reloads independently from the web server. If behavior seems stale, restart that worker process.
- `console.log` in a handler shows up in whichever process ran the job - check both terminals.
- Env vars are read at process start; `.env` edits need restarts.

## Jobs: things that look like bugs but aren't

- A failed job does not retry automatically. Use the UI's Retry action after correcting the key or input; it creates a new job row and re-runs the whole handler.
- `POST /api/jobs` can return an **old** job (dedup). If "Generate" seems to do nothing, an identical job is already queued/processing.
- Failed job with "No active API key found for provider X" - the user needs to add the key (or the code looked up the wrong `keyProviderId`).

## Regeneration doesn't delete

Everything is latest-wins (see [conventions.md](/database/conventions)). If a UI shows an old asset after regeneration, the bug is almost always a read path that isn't sorting `created_at DESC` + deduping per label - not leftover data.

## Timestamps drift if you skip the recalc

Any code that changes scene `duration` or order must run `recalcTimestamps` + `persistTimestamps` (from `useScenes`). Symptoms of forgetting: AudioPlayer highlights the wrong scene; export manifest times are wrong.

## Supabase errors are return values

```ts
const { data, error } = await supabase.from(...).select(...)
```
Nothing throws. Forgetting to check `error` (or that `.single()` errors when 0 rows match) silently gives you `data = null`. Note `GET /api/settings` specifically handles error code `PGRST116` ("no rows") to auto-create defaults.

## Windows quirks

Development happens on Windows: never build shell strings for ffmpeg (the code uses `execFile` arg arrays - keep it that way), and the export/concat code normalizes `\` to `/` when writing ffmpeg concat list files - copy that if you write similar code.

## Misc

- Export uses `VIDEO_FORMAT` as the fixed output size. If you change aspect ratio or resolution, update the ffmpeg normalization in `server/worker/handlers/export.ts`, provider presets, and the docs together.
- `music` and `publish` job types exist but instantly fail ("not yet implemented").
- The `#supabase/server` alias in `nuxt.config.ts` deliberately overrides the Supabase module's own server helpers with the project-local `supabase-server.ts` - don't remove the alias block.
- Historical planning notes are not part of the public repository. Keep durable, current guidance in `docs-site/` instead.
